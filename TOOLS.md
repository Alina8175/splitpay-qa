# Отчёт по инструментам

Что смотрели, зачем оно было нужно и почему в этом окружении не встало.
Отчёт короткий намеренно: инструменты, которые не удалось поставить,
оцениваются по назначению и по причине отказа, а не по впечатлениям
от чтения их описаний.

**Общая причина отказа у всех трёх — одна.** Реестр npm закрыт исходящим
прокси из обеих сред: `npm ping` → `E403`, `curl` → `HTTP code 403 from proxy
after CONNECT`. Вывод целиком — `evidence/env-check.md`. Это не «не успели
поставить» и не «решили не ставить»: канал установки физически отсутствует,
и обойти его нечем — офлайн-зеркала, кеша пакетов и возможности принести
архив руками в этой сборке тоже нет.

## Superpowers

**Что это.** Набор надстроек над агентом: библиотека готовых навыков
(skills), которые подключаются к сессии и дают агенту заранее написанные
процедуры вместо того, чтобы он изобретал их каждый раз заново.

**Зачем был нужен здесь.** Ровно под ту работу, которую в этом проекте
пришлось писать руками: повторяемая процедура прогона, сборка отчёта из
файлов-доказательств, дисциплина «шаг без файла не считается сделанным».
`workflow/qa-regress` — это, по сути, самодельный навык на bash.

**Почему не встал.** Ставится из npm. Реестр закрыт.

**Что из этого следует.** Отсутствие библиотеки навыков стоило времени,
но не качества: процедура написана под конкретный проект и понятна целиком,
её можно прочитать за десять минут и оспорить построчно. Готовый навык
дал бы скорость и отнял бы прозрачность — в работе, которую сдают
за обоснованность решений, это не очевидный размен.

## GitNexus

**Что это.** Надстройка для работы с git из агента: обзор истории, ветвления,
подготовка коммитов и разбор изменений без ручных команд.

**Зачем был нужен здесь.** Проект живёт git-историей: 23 коммита, три
worktree, три ветки, три `merge --no-ff`, тег как точка отсчёта регрессии.
Всё это делалось руками, и именно здесь случились два из восьми эпизодов
раздела «Что не сработало» — мёртвые замки после архивации и `prune`,
пропускающий заблокированные записи.

**Почему не встал.** Ставится из npm. Реестр закрыт.

**Отдельно и важнее.** Даже поставленный, он не решил бы главную проблему
git в этом проекте: **среда на машине заказчика запрещает удаление файлов**
(риск Р-1). Надстройка над git наследует ограничения git. Она бы удобнее
показывала историю — и так же падала бы на `Unable to create index.lock:
File exists`.

## context-mode

**Что это.** Управление тем, что именно попадает агенту в контекст: какие
файлы подтягиваются, какие режутся, как удерживается рамка на длинной работе.

**Зачем был нужен здесь.** Это самая дорогая проблема всей работы. Четыре
сессии, репозиторий, где отдельные файлы по 100–140 КБ, лимиты, дважды
оборвавшие веер субагентов на полном ходу. Половина решений в
`sessions/STATE.md` — про то, как не втянуть в контекст лишнего.

**Почему не встал.** Ставится из npm. Реестр закрыт.

**Чем заменили.** Тем же, чем и всё остальное, — договорённостью и файлом.
`sessions/STATE.md` — передаточный контракт: агент, прочитавший только его,
должен ответить, что сделано, что делать дальше и чего делать нельзя.
Это ручной context-mode: не инструмент, а протокол. Работает, но требует
дисциплины на каждом шаге и ломается ровно там, где дисциплину нарушили —
случай Н-8 в `REPORT.md` (два промпта записаны задним числом).

## Токен GitHub агенту: рассматривали, отказались

Выдача агенту токена GitHub решила бы последний ручной шаг работы —
публикацию: агент сам делал бы `push`, и человек в цепочке не был бы нужен
вовсе. **Отказались.**

Причина не в общей осторожности, а в устройстве именно этой сдачи.
**Журнал промптов ведётся дословно и лежит в публичном репозитории**
(`sessions/session-*.md`). Промпт, которым токен передаётся агенту,
по правилу 6 должен быть записан в журнал до выполнения — дословно,
вместе с самим токеном. То есть токен утёк бы не через ошибку, не через
лог и не через агента, а **через собственную сдачу работы**, ровно тем
механизмом, который в этом проекте отвечает за честность.

Обходы рассматривались и отклонены:

| Обход | Почему нет |
|---|---|
| Записать промпт с замазанным токеном | Нарушает дословность журнала — единственное, что делает журнал доказательством |
| Передать токен вне журнала | То же самое, только неявно: действие без записанного промпта |
| Ослабить образец в `pre-commit` хуке | Хук ловит присваивания ключей именно в журнале. Журнал промптов — как раз то место, куда реальный ключ и попадёт |
| Токен с узкими правами | Уменьшает ущерб, не устраняет утечку. Публично лежащий токен остаётся публично лежащим токеном |

**Вывод.** Публикация осталась единственным шагом, который делает человек, —
и это не недоработка автоматизации, а плата за дословный публичный журнал.
Из двух вещей — «агент делает всё сам» и «видно, что именно ему говорили» —
выбрана вторая. Разбор границ песочницы, показывающий, почему это ограничение
не техническое, а принятое, — раздел «Изоляция» в `REPORT.md`.
