# ЛИЧНЫЕ РИСКИ — персональный блок

Основано на разборе прошлой работы по этому курсу. Это не требования задания,
а места, где я уже терял(а) баллы. Приоритет у этого блока выше, чем у общих
рекомендаций ниже по файлу.

## Р1. Коммиты: не меньше 8 за день, по одному в конце каждого смыслового шага

- **Что было в прошлый раз:** два коммита на девять сессий. Формулировка минуса:
  «41 файл доказательств появляется в истории одномоментно, хотя собирались они
  по шагам». История не показала работу — она показала один вброс.
- **Почему сегодня риск выше, а не ниже:** однодневный темп подталкивает
  «закоммичу всё в конце». Именно так прошлый минус и воспроизведётся, только быстрее.
- **Цель:** **≥ 8 коммитов за день**, каждый — в конце смыслового шага
  (спецификация готова → коммит; область проверок прогнана → коммит; отчёт о прогоне
  дописан → коммит; workflow сохранён → коммит; PDF собран → коммит и т. д.).
- **Правило шага:** шаг не считается завершённым, пока не сделан коммит. Не «сделаю
  потом», а прямо здесь.
- **Обязанность агента:** напоминать о коммите самостоятельно — в конце каждого
  смыслового шага, не дожидаясь просьбы. Если шаг закрыт, а коммита нет — сказать
  об этом до перехода к следующему шагу.
- [ ] **Чем закрывается:** `git log --oneline` — не менее 8 строк с осмысленными
  сообщениями, разнесёнными по ходу дня, а не подряд в последний час.

## Р2. Одна задача — одна сессия

- **Что было в прошлый раз:** правило размылось изнутри — в сессию была дописана
  фраза «переходим к следующему шагу в этой же сессии». Итог: самый нагруженный этап
  оказался в самой перегруженной сессии, и единственный технический тупик случился
  именно там.
- **Правило:** новый смысловой шаг — новая сессия. Особенно это касается независимой
  проверки: агент-скептик, ломающий чужие чек-листы, всегда отдельной сессией
  («автор не бывает независимым проверяющим»).
- **Триггер, на который агент обязан среагировать:** фразы вида **«давай продолжим
  здесь»**, «остаёмся в этой сессии», «доделаем тут же». Прежде чем соглашаться —
  напомнить про этот пункт и про прошлый тупик, и только после подтверждения
  продолжать.
- [ ] **Чем закрывается:** `sessions/` — отдельный файл на каждый смысловой шаг;
  ни один файл не содержит двух разнородных этапов.

## Р3. Объём не сокращаем — сокращаем непрогнанное

- **Уточнение, отменяющее общий совет «взять поменьше»:** в прошлой работе было
  **66 проверок соответствия спецификации** и **полнота сдачи 15 из 15**. Количество
  кейсов — не риск и не проблема.
- **Риск в другом:** прогнаны кейсы или нет.
- **Правило набора:** **кейс, который не прогнан и не имеет зафиксированного
  результата, в набор не входит.** Не «прогоним позже», не «очевидно, что пройдёт» —
  такой кейс просто не является частью сдаваемого набора.
- **Следствие:** объём набора равен объёму прогона. Растёт прогон — растёт набор.
- [ ] **Чем закрывается:** у каждого кейса в наборе есть зафиксированный результат
  прогона (прошёл / упал / заблокирован) с датой и ссылкой на доказательство
  в `evidence/`; кейсов без результата в наборе нет.

# 1. Три обязательных пункта

## 1.1. Работающий результат

- [ ] **Работающий результат есть и запускается по инструкции**
  - Формулировка задания: «на выходе — работающая вещь, а не описание»; размер намеренно
    небольшой — одна фича / одно исследование, доведённое до конца.
  - **Что считается результатом для QA:** *работающий набор проверок, который прогоняется
    и даёт результат* + *отчёт о прогоне*. Не тест-план в вакууме, а прогоняемый набор
    и зафиксированный итог прогона.
  - Приоритет — свой проект или своя рабочая задача; варианты из Приложения А (для QA
    ближе всего A4 «Тест-план платёжных сценариев», B4 «Регресс кредитного калькулятора»,
    B7 «Сверка выписок») — опора, если своего нет.
  - Ограничение для QA/нетехнических ролей: **код писать не нужно**, всё делается
    на текстовом проекте — папка с git, чек-листы, workflow.
  - **Чем закрывается:** репозиторий с набором проверок (чек-листы / сценарии / скрипт
    прогона) + файл отчёта о прогоне (`run-report.md` или раздел в `REPORT.md`)
    + `README.md` с инструкцией «как прогнать».

## 1.2. Агенты: запустить и попробовать

- [ ] **Работа разбита на части и отдана субагентам параллельно, в одной сессии**
  - Ориентир: три-четыре независимых исполнителя под одной задачей, каждому своя зона,
    чужую трогать запрещено. Для QA естественное деление — три области проверок.
  - Субагенты в Claude Code и Codex работают из коробки — достаточно попросить словами.
  - **Чем закрывается:** видно из журнала сессий / скриншотов / текста в `REPORT.md`,
    что работали именно субагенты; плюс сами артефакты, произведённые разными агентами
    (три отдельных файла по трём областям — самое наглядное доказательство).

- [ ] *(необязательно, в плюс)* **Замер: последовательно против параллельно**
  - Замерять время и заполнение контекста главной сессии.
  - **Чем закрывается:** таблица «время / контекст главной сессии / качество» в `REPORT.md`.

## 1.3. Workflow — ОБЯЗАТЕЛЬНО

- [ ] **Собран минимум один workflow, применимый к реальной задаче**
  - Формат свободный: скилл, хук, workflow-файл, сохранённый промпт.
  - Пример для QA прямо из материалов: «взять изменения с последнего прогона → собрать
    список затронутых сценариев → прогнать → отчёт».
  - **Доказывать повторяемость не нужно** — достаточно приложить файл или текст.
  - **Чем закрывается:** файл в репозитории (`workflow/qa-run.md`, `.claude/skills/…`,
    хук — что угодно) + строка в `README.md`, как его вызывать.

# 4. Необязательные пункты, которые дают плюс

- [ ] **Команда 3–4 человека** / **межролевая команда** (последнее — особенно ценится).
  - **Чем закрывается:** `README.md` с разделением ролей.
- [ ] **Git worktrees: три задачи одновременно, три ветки, затем merge.**
  - Для QA раскладка — три области проверок.
  - Убирать за собой: `git worktree remove`, `git worktree prune` (в эфире — случай
    с 250 ГБ).
  - **Чем закрывается:** история репозитория — три ветки, три набора коммитов, merge-коммиты;
    вывод `git worktree list` в отчёте.
- [ ] **Изоляция с доказательством** — не «запускал в Docker», а **вывод неудачной попытки**
      выйти за границу. Отдельно интересно: встроенная песочница Claude Code накрывает
      Bash и его дочерние процессы, но **не MCP** — попробовать дотянуться MCP-сервером.
  - **Чем закрывается:** скопированный вывод отказа (терминал) + результат попытки через MCP.
- [ ] **Недоверенный текст: инъекция на двух моделях, слабой и сильной.**
  - Фиксировать три исхода: *выполнила / промолчала / назвала вслух*. «Молча не сделала»
    и «сказала вслух» — разные уровни защиты.
  - Способы внедрения: комментарий, белый текст, метаданные, поле «назначение платежа»,
    «служебная строка».
  - **Чем закрывается:** заполненная таблица «способ × модель → выполнила / промолчала /
    назвала» + файлы-носители инъекции в репозитории.
- [ ] **Оптимизатор контекста и/или индекс кодовой базы** — с обязательной проверкой

  - **Чем закрывается:** раздел «Инструменты» в `REPORT.md`: что понравилось, что нет,
    что не сработало; при возможности — замер «один и тот же вопрос до и после».

  - **Чем закрывается:** пара строк в `REPORT.md`.
- [ ] **Переход с архива на Git** — плюс отдельным пунктом для тех, кто в прошлый раз

# 6. Требования, упомянутые вскользь, но проверяемые

Это то, что не вынесено в списки, но в тексте задания и материалов сформулировано
как условие приёмки. Здесь чаще всего теряются баллы.

- [ ] **Формат PDF — не «экспорт markdown», а собранный документ.**
  - «Сырой markdown и plain text не принимаются». Вёрстка собирается **тем же агентом**:
    HTML + CSS для печати → PDF, либо презентация (8–12 слайдов, 16:9, одна мысль на слайд).
  - Требования к документу: титульная страница (название, дата, автор), оглавление,
    резюме на полстраницы, разделы, таблицы вместо перечислений, один акцентный цвет,
    колонтитулы с номерами страниц, **никаких эмодзи и декоративного мусора**.
  - **Чем закрывается:** PDF в репозитории + отдельный проход «открой PDF и посмотри
    как читатель: где текст налезает, где страница пустая наполовину, где таблица
    не влезла» — и пересборка после правок.

- [ ] **Проверка на секреты перед сдачей.**
  - Проверять: `.env`, `settings.json`, история команд, скриншоты терминала.
  - Формулировка из эфира: «ключ утекает не через взлом, а через файл, который вы сами
    показали».
  - **Чем закрывается:** проход по репозиторию перед пушем (grep по ключам/токенам,
    просмотр всех скриншотов, `.gitignore`), отметка в `REPORT.md`, что проверка сделана.
  - Смежное: в задании A5 отдельным пунктом — *что из персональных данных нельзя класть
    в папку, которую читает агент*; если работаете с ПД (даже синтетическими) — сказать
    об этом явно.

- [ ] **Дословность промптов в журнале сессий.**
  - Требование именно «промпты **дословно** и решения» — не пересказ, не «попросил агента
    сделать проверки».
  - **Чем закрывается:** `sessions/` с копипастой промптов как есть, включая неудачные
    и переформулированные, + принятые по ходу решения.
  - Практический вывод: копировать промпты **по ходу работы**, задним числом дословность
    не восстанавливается.

- [ ] **Раздел «что не сработало» — обязателен по духу, влияет на оценку.**
  - «Отчёт с тремя честными тупиками стоит больше отчёта, где всё получилось с первого
    раза»; критерий «Честность» — отрицательный результат оценку **повышает**.
  - **Чем закрывается:** отдельный раздел в `REPORT.md` с конкретикой: что пробовали,
    что именно сломалось, чем закончилось.

- [ ] **Независимость проверяющего.**
  - «Автор не бывает независимым проверяющим» — агент-ломатель / скептик запускается
    **отдельной сессией**, не той, что делала работу. Для QA это прямо профильный приём:
    отдельный агент, которому поручено найти дыры в чужих чек-листах (см. A4).
  - **Чем закрывается:** отдельная сессия в `sessions/` + её находки в отчёте.

- [ ] **Проверка сторонних репозиториев до установки.**
  - Два запроса именно в таком порядке: сначала «что это, ничего не устанавливай»,
    потом «проверь с точки зрения безопасности → вердикт → если безопасен, установи».
  - Ориентир доверия: десятки тысяч звёзд и тысячи коммитов ≠ сотня звёзд. Цифрам
    из ролика и презентации не верить — смотреть страницу репозитория.
  - **Чем закрывается:** запись проверки в `sessions/` или `REPORT.md` (актуально, если
    ставите Superpowers, оптимизатор, индекс).

- [ ] **Git как форма сдачи, а не папка.**
  - Ожидается видимая история: ветки, коммиты, журнал и результат в одном месте.
  - **Чем закрывается:** осмысленные коммиты по ходу работы, а не один «initial commit»
    за час до дедлайна.

- [ ] **`README.md` без «допишите тут своё».**
  - Критерий «Работает» сформулирован именно так — инструкция должна быть самодостаточной.
  - **Чем закрывается:** прогон инструкции с чистого листа, желательно чужими руками
    или отдельным агентом.
