## Две дыры в защите, найденные этой проверкой и закрытые

Проверка делалась ради подтверждения, что всё чисто, и нашла обратное — две
незакрытые щели. Обе закрыты 28 августа.

### 1. `_pending/` и `_do-git-steps.sh` не были в `.gitignore`

`sessions/STATE.md` утверждал, что рабочие остатки сессии 3 «внесены
в `.gitignore`, в репозиторий не входят». Фактически внесены были только
`_transfer/` и `evidence/hook-demo.txt`. `_pending/plan-b.spec.mjs`
и `_do-git-steps.sh` не игнорировались и уехали бы в репозиторий с первым же
`git add -A`.

```
_do-git-steps.sh                         НЕ ИГНОРИРУЕТСЯ
_pending/plan-b.spec.mjs                 НЕ ИГНОРИРУЕТСЯ
_transfer/app.tgz                        IGNORED
evidence/hook-demo.txt                   IGNORED
```

Закрыто: в `.gitignore` добавлены `_pending/`, `_do-git-steps.sh`, `_to_delete/`.

### 2. Защита материалов курса держалась на одном символе-разделителе

И `.gitignore`, и `pre-commit` опознавали материалы курса по точному имени
с разделителем `·` (U+00B7). Разделитель в имени файла — одиночный символ,
который легко перепутать: `·`, `•`, `-`, `—`. Промах на один символ отключает
оба правила молча, ровно тем способом, которым первая версия хука уже один раз
пропустила материалы курса (случай Н-2 в `REPORT.md`).

Проверить фактическое имя файла на машине из этой сессии оказалось нельзя:
файловый мост вернул имена в испорченной кодировке, а инструмента запуска
команд на машине в этой сборке нет. То есть **утверждение «проверено через
`git check-ignore`» из `STATE.md` в этой сессии подтвердить было нечем.**

Закрыто не проверкой, а расширением правила: и в `.gitignore`, и в хуке
добавлены широкие маски `04 *` / `05 *` по префиксу. Теперь правило
не зависит от того, какой именно символ стоит третьим.

```
04 — Домашнее задание №2.pdf   →  IGNORED (широкая маска работает)
```

**Что всё равно стоит сделать руками на машине,** потому что проверка
механизма отказом — правило 9, а не пожелание:

```
git check-ignore -v 04*.md 04*.pdf 05*.md 05*.pdf
```

Вывод должен назвать сработавшее правило для каждого из четырёх файлов.
Пустой вывод означает, что файл НЕ игнорируется.
