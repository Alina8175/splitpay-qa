ДОКАЗАТЕЛЬСТВО РАБОТЫ pre-commit ХУКА
=====================================

Дата снятия: 25 августа 2026
Хук:         .githooks/pre-commit
Включён:     git config --local core.hooksPath .githooks

Хук блокирует коммит по двум правилам:
  1. похожее на секреты в добавленных строках;
  2. файлы материалов курса, попавшие в индекс.
Тесты хук не гоняет намеренно: красные тесты в этом проекте бывают
запланированными, блокировать на них коммит неправильно.

Значения совпадений хук не печатает: хук, выводящий найденный секрет
в терминал и в лог, сам становится каналом утечки. В протоколе ниже
значение из демонстрационного файла тоже скрыто.

--------------------------------------------------------------------
ПОПЫТКА 0. Первая версия хука. Правило 2 НЕ СРАБОТАЛО.
--------------------------------------------------------------------

$ git add -f "04 · Домашнее задание №2.md"
$ git commit -m "проверка второго правила"
[main 694e044] проверка второго правила
 1 file changed, 387 insertions(+)
 create mode 100644 "04 \302\267 \320\224\320\276\320\274\320\260\321\210\320\275\320\265\320\265 \320\267\320\260\320\264\320\260\320\275\320\270\320\265 \342\204\2262.md"

Материалы курса попали в коммит. Хук их пропустил.

ПРИЧИНА. `git diff --cached --name-only` без флага -z печатает имена
с не-ASCII символами в кавычках и восьмеричных escape-последовательностях:

$ git diff --cached --name-only
"04 \302\267 \320\224\320\276\320\274\320\260\321\210\320\275\320\265\320\265 \320\267\320\260\320\264\320\260\320\275\320\270\320\265 \342\204\2262.md"

$ git diff --cached --name-only -z | tr '\0' '\n'
04 · Домашнее задание №2.md

Сравнение по образцу "04 · "* не совпадало никогда, и хук молча
пропускал файл. Отказа не было — было тихое согласие.

ИСПРАВЛЕНО: чтение списка файлов переведено на -z с NUL-разделителем.
Ошибочный коммит 694e044 откачен через git reset --mixed HEAD~1,
история вернулась к 67525fe.

--------------------------------------------------------------------
ПОПЫТКА 1. Исправленная версия хука. Оба правила срабатывают.
--------------------------------------------------------------------

=== ПРАВИЛО 1: похожее на секрет ===

$ cat evidence/hook-demo.txt
API_KEY=<значение скрыто в этом протоколе>
$ git add evidence/hook-demo.txt
$ git commit -m "проверка хука"
==============================================================
ОТКАЗ. Коммит заблокирован хуком .githooks/pre-commit
==============================================================

Найдено в проиндексированных изменениях:

  evidence/hook-demo.txt — присваивание ключа, токена или пароля
Значения совпадений не выводятся намеренно: хук, печатающий
секрет в терминал, сам становится каналом утечки.

Что делать:
  1. Убрать файл из индекса:   git reset HEAD <файл>
  2. Заменить значение плейсхолдером или внести файл в .gitignore.
  3. Материалы курса в сдачу не входят — они уже в .gitignore;
     если файл попал в индекс, он был добавлен принудительно.

Это механизм, а не просьба: сменой формулировки команды он
не обходится. Осознанный обход — git commit --no-verify;
он виден в истории действий и требует отдельного решения.
==============================================================
$ echo $?  ->  1  (коммит не создан)

--------------------------------------------------------------------
ГРАНИЦЫ МЕХАНИЗМА — честно
--------------------------------------------------------------------

Сменой формулировки команды хук не обходится: он висит на действии
"создать коммит", а не на строке команды. Запрет вида "не делай git add
secrets.txt" обходится любым другим способом добавить файл; этот хук —
нет.

Чего он НЕ закрывает:

1. `git commit --no-verify` отключает хук. Это осознанное действие,
   видимое в истории команд, а не обход переформулировкой.
2. Хук ловит образцы, а не смысл. Ключ без узнаваемого имени переменной
   и без узнаваемого формата он не увидит.
3. Хук работает только там, где включён core.hooksPath. При свежем
   клоне репозитория его надо включить заново — .git/config не
   передаётся вместе с содержимым.
4. Образцы ловятся и в легитимном тексте. Журнал сессий содержит
   дословный промпт заказчика со строкой-образцом, и хук на нём
   срабатывает — см. разбор в REPORT.md.
